Safety and privacy

Snapshots before AI sessions

PoHo saves your project before every AI session, so you can put back any file an agent broke.

Before an AI session starts, PoHo saves your project, so you can put back anything an agent broke, one file or all of them. You don’t have to do anything: it happens on its own for every project that uses git.

When a snapshot is taken

  • When you continue or start a chat from PoHo.
  • When Claude Code or Cursor starts a session on its own, if you connected them in Settings → AI agents.
  • When you click Save snapshot now.

Where snapshots live

Snapshots are hidden inside the project’s own .git folder. They never change your files, branches or history, and a normal git push doesn’t send them. PoHo keeps the newest 30.

.env files are never saved in a snapshot, and never restored over. Files your .gitignore leaves out, such as node_modules, aren’t saved either.

See what changed and put files back

  1. Open the project and go to Setup.
  2. In Snapshots, click a snapshot to see the files that changed since.
  3. Click Restore next to one file, or Restore all.
  4. Confirm.

You can also open a session on the Sessions tab and fold open What this session changed.

When you restore, PoHo saves the current state first, so you can undo it. If that safety snapshot can’t be made, nothing is restored. Files that are new since the snapshot are left as they are.

When there is no snapshot

  • The project doesn’t use git. Snapshots need git.
  • Nothing changed since the last snapshot.
  • More than 5,000 untracked files, often a node_modules folder without a .gitignore.
  • The project’s git settings name a program to run. PoHo doesn’t touch such a repository, to keep you safe.

Note: The Snapshots list shows the newest 10.
